# ADR-0005: koyu の特定のコミットに対して手元で穿つを動かす

日付: 2026-07-26 / 状態: 採用 / 起点: 「koyu側の確認をnpmをパブリッシュしないと穿つで確認できないのは痛い」

## 文脈

ADR-0002 は穿つが koyu を**パッケージとして**消費すると決めた。ビュアーは答えを持たず、導出はすべて koyu への呼び出しである、という関係を依存として明示するためで、この決定は正しい。CIも「依存はすべてnpmレジストリから来る (git依存ゼロ) ので lockfile を信じてよい」という前提で立っている。

代償が一つあった。**koyu 側の変更を穿つで確かめるのに npm への公開が要る。**

実際に痛かった。koyu に縦動線・柱・面の要素を入れた回、平面と3Dで確かめたいのに、確かめる手段が「公開してから入れ直す」しかない。公開は取り消せない操作なので、まだ形が定まっていないものを公開する圧力がかかる。**確認したいから公開する、という順序が逆立ちしている。**

その場しのぎで `node_modules/@kensnzk/koyu` を手で symlink して凌いだが、これは三重に悪い。`npm install` で黙って消える。今どちらを見ているかがどこにも出ない。そして「作業ツリー」しか見られないので、**「あのコミットの koyu でこの図はどう出ていたか」に答えられない**。

## 決定

**1. `node_modules/@kensnzk/koyu` を対象へのシンボリックリンクに差し替える、を正式な手順にする。**

`scripts/koyu-local.mjs` と三つのスクリプトで包む。

```sh
npm run koyu:local              # 隣の作業ツリー (../koyu_core) を見る
npm run koyu:local -- aef5b67   # そのコミットを取り出して見る (タグ・ブランチも可)
npm run koyu:status             # 今どれに繋がっているか
npm run koyu:unlink             # レジストリの版へ戻す
```

シンボリックリンク一本にしたのは、**vite も tsc も vitest も同じ解決を通る**からである。バンドラのaliasだけを差し替えると、型検査とテストが別のものを見てしまい、「dev では動くが typecheck が落ちる」という最悪の状態を作る。解決の入口は一つにする。

**2. 特定のコミットは git worktree で取り出す。**

`.koyu/<commit>/` に detached worktree を作る (gitignore 済み)。同じコミットなら作り直さない。取り出したツリーに `node_modules` は無いが、**koyu は実行時依存ゼロ**なのでビルドに要るのは typescript だけであり、本体の `node_modules` を貸すだけで済む。取り出しごとに `npm install` は走らない。

これで **「koyu のこのコミットに対して穿つはどう動くか」が一行で再現できる**。バグの二分探索も、過去の図の再現も、同じ入口を通る。

**3. 今どれに繋がっているかを必ず言葉にする。**

`koyu:local` も `koyu:unlink` も最後に `status` を出す。**見えない差し替えは事故のもと**で、レジストリ版のつもりでローカル版を見ていた、はいちばん高くつく間違いである。バージョン・ref・コミット・実体のパスを出す。

**4. CI は何も変えない。**

`.koyu/` も `.koyu-local.json` も node_modules も gitignore にあり、CIは `npm ci` でレジストリから入れ直す。**リンクは構造的にCIへ漏れない。**したがって「手元では通るがCIで落ちる」は起こりうるし、起こってよい — それは公開すべき版がまだ公開されていない、という正しい知らせである。

## 代替案

**vite の resolve.alias だけを差し替える。** 最小の変更で、koyu の**ソース**を直接見られるのでビルドすら要らない (HMRも効く)。採らなかったのは決定1の理由 — tsc と vitest が別のものを見る。dev だけ通って型が合っていない状態は、ビュアーの側の実装ミスをkoyu側の変更のせいに見せる。

**npm workspaces でモノレポにする。** リンクの問題は消えるが、ADR-0002 が「別のリポジトリの、パッケージとしての依存」に置いた意味 — ビュアーが答えを持たないことを依存関係として強制する — が薄れる。二つの規律 (koyuは公開APIだけを見せる / 穿つはそれ以上を使えない) がモノレポでは緩む。

**CIで koyu を git checkout して束ねる。** 穿つのCIが「npmレジストリだけを信じる」構えを崩す。lockfile が全てを決めているという性質は、単一HTMLを配布物にする方針 (ADR-0004) と対になっているので崩したくない。

**プレリリース版を公開して繋ぐ (`0.12.0-rc.1`)。** 公開の取り消せなさは残るが、mainを汚さずに回せる。**併用できる**ので棄却ではない — 手元で固めるのが `koyu:local`、他人に渡すのがプレリリース、と役割が分かれる。

## 帰結と代償

**得たもの。** koyu の変更を、公開せずに、平面と3Dで確かめられるようになった。「確認したいから公開する」という逆立ちが解けた。過去のコミットに対する再現ができるようになったのは副産物だが、記法が版を持つ (koyu ADR-0017) 以上、**版ごとに図がどう変わるかを見られること自体に意味がある**。

**代償1: リンク中は lockfile が嘘をつく。** `package.json` は `^0.12.0` と言っているのに実体は作業ツリーである。`koyu:status` がその嘘を可視にするのが唯一の防御なので、迷ったら叩く。

**代償2: 手元とCIがずれる。** 未公開のAPIを使うと、手元は緑でCIは `npm ci` の ETARGET で落ちる。これは**設計どおり**である — 公開の順序を守れという知らせであって、隠すべき不具合ではない。

**代償3: worktree が溜まる。** `.koyu/` は消さない限り残る。`git -C ../koyu_core worktree prune` と `rm -rf .koyu` で片付ける。自動で消さないのは、二分探索の途中で消えると困るからである。
