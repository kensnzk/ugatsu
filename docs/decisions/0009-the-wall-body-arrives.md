# ADR-0009 (ugatsu): 壁の実体は届く — 芯線に厚みを振るのをやめる

日付: 2026-08-18 / 状態: 採用 / 前提: koyu [ADR-0063](https://github.com/kensnzk/koyu/blob/main/docs/decisions/0063-the-wall-body-is-derived-with-its-junctions-closed.md)・[ADR-0058](https://github.com/kensnzk/koyu/blob/main/docs/decisions/0058-the-constructors-of-matter-are-public.md)、ugatsu [ADR-0007](0007-draw-the-form.md)・[ADR-0008](0008-follow-muro-1-3.md)

## 文脈

koyu 0.22.0 は**言語を一つも動かしていない**。muro は 1.3 のままで、読み方も、書き方も、移行も無い。動いたのは導出だけである。

動いたのは一点で、それが ugatsu の一番深いところに当たった。

**境界の区間が `footprint` を持って届くようになった。**両端の取合いが既に決まった足あとである。芯線 (`x1,y1,x2,y2`) はそのまま残っているが、**もう足あとの軸ではない** — 節点を勝った壁はその先へ伸び、負けた壁は勝った壁の面で切られるので、芯線と厚みからは足あとが戻らない。

ugatsu はその戻らないものを、毎フレーム組み立てていた。`buildScene.ts` の `panelMesh` が `segBox(p, p.z0, p.z1, t)` を呼び、芯線に厚みを両側へ振って箱を立てていた。**直角に交わる二枚の壁が共有する点の外側に、t/2 × t/2 の升がどちらの壁にも属さないまま残る。**

穴は描かれた立体に対して数えた。レベルごとに、端点を共有する二枚の壁が作る隅の升の中心を取り、シーンに立った壁のどれかがそこを覆っているかを訊く。

```text
two-rooms.muro     8 / 8       office.muro     61 / 61
house             25 / 25      basement        49 / 49
mansion.muro     511 / 511     tower          716 / 716
complex        1,606 / 1,606   twin         7,024 / 7,024
```

**一つも覆われていない。**分母は標本の数であり、koyu ADR-0063 が数えた数 (two-rooms で 4) とは母集団が違う — あちらは平面で節点ごとに一升、こちらはレベルごとに壁の端の組ごとである。言っていることは同じで、**ugatsu の 3D は隅という隅が開いていた。**

**この一件をテストが見逃していた。**`test/form.test.ts` の `expectedBoxes` が、壁の期待値を実装と同じ式 — 芯線と厚みから箱 — で組んでいた。実装が壊れていても期待値が同じ壊れ方をするので、集合は一致し、検査は緑になる。ADR-0008 が `expectedMarks` で踏んだのと同じ穴を、立体の側にもう一つ空けていた。

平面は無事だった。`planFigure` は plan エンティティの `polygon` を見ており、そこに来るのは 0.22.0 では接合済みの足あとである。ADR-0008 決定4.1 が「足あとを先に見る」へ入れ替えた読む順が、**何も知らないまま新しい導出を拾っていた。**

## 決定

**1. 壁の実体は押し出す。組み立てない。**

`panelMesh(p, mat)` は `p.footprint` を z0..z1 へ押し出すだけである。**厚みを受け取らない** — 受け取っても使い道が無い。取合いの決まった実体は芯線と厚みの関数ではないので、厚みを渡せる形にしておくこと自体が、いつか誰かがまた組み立てる余地になる。

`thicken` は import から消えた。ADR-0008 決定4 が「構成子は koyu から取る」と決めたのはいまも正しく、`bandLine` (建具の帯) と `runPrism` (斜路) は取り続ける。**壁だけが構成子の対象から外れた**のは、koyu ADR-0063 が壁についてだけ ADR-0058 を撤回したからである。

**2. 期待値は `Form` の輪郭から組む。実装の式からは組まない。**

`expectedPrisms(form)` が、壁の足あと・空間の気積・面 (床・天井・屋根) の輪郭を `Form` からそのまま集める。壁は `expectedBoxes` から抜けた — 箱として書き直せば、期待値の側にも取合いの開いた壁を書くことになる。

**3. 隅に穴が無いことを、描かれた立体に対して数える。**

「壁の取合いは閉じている」が同梱例8件すべてで、上の標本を立てて覆われていることを言う。標本が空なら何も言っていないので、母集団が空でないことも同時に縛る。**芯線から箱を起こす実装はこの検査で落ちる** — 実際、旧実装へ戻すと8件すべてが落ち、`expectedPrisms` との一致も含めて 26 件が赤くなる。

**4. 平面は何も変えない。**

変えなかったことを記録に残す。0.22.0 で平面が正しいのは ADR-0008 の読む順のおかげであって、偶然ではない — が、`planFigure` が `e.polygon` を先に見ることに依存している、という一行の依存が新しく生まれた。それを言うのは「壁の足あと・気積・面が `Form` の輪郭のまま押し出される」と、既にある「材を持つ境界は帯として描かれる」の二つである。

**5. 版を上げる。**

ugatsu 0.7.0 / `@kensnzk/koyu` ^0.22.0。同梱例は `npm run sync-examples` で追随した — 0.22.0 は例の本文から寸法の台帳を外しており、`complex/core.muro` と `twin/main.muro` の注釈が変わっている。**形は動いていない。**

## 帰結、実測

**同じ建物で、隅だけが閉じた。**面積の四例も、平面の印の数も、上部吹抜けの11件も動いていない。芯線と関係 (`FormBoundary.segment`、正準順の索引) は 0.22.0 が触っていないので、面積表も選択もインスペクタも `written.ts` の道も影響を受けない。

| 増えた検査 | 何を縛るか |
|---|---|
| 壁の足あと・気積・面が `Form` の輪郭のまま押し出される | 押し出しの輪郭を一つでも捏造すれば落ちる。**数ではなく集合で突き合わせる** |
| 端点を共有する壁の隅に穴が無い | 芯線から実体を組み立てる実装が8件で落ちる |
| 押し出しの数 = 気積 + 面 + 壁の区間 | 壁が押し出しの母集団に入ったことを数で押さえる |

**残る借り。**IFC 書き出しは koyu 側で接合を持たない (ADR-0063「帰結」) が、ugatsu は書き出しを持たないので関係が無い。`validate` を呼ばないこと、機械形式を読めないことは ADR-0008 のまま動いていない。
