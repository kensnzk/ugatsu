# ADR-0007 (ugatsu): 形を組み立てるのをやめ、`Form` を描くだけにする

日付: 2026-07-28 / 状態: 採用 / 前提: koyu [ADR-0040](https://github.com/kensnzk/koyu/blob/main/docs/decisions/0040-derive-reference.md)・[spec/derivation.md](https://github.com/kensnzk/koyu/blob/main/spec/derivation.md)・[spec/scope.md](https://github.com/kensnzk/koyu/blob/main/spec/scope.md) §6、ugatsu [ADR-0005](0005-local-koyu-pipeline.md)・[ADR-0006](0006-scope-and-boundary.md)

## 文脈

ugatsu 1.0 が凍結する四つの面のうち、**「導出の一致 — 参照実装と同じ形を作る」だけが検査しようがない**まま残っていた ([docs/scope.md](../scope.md) §1)。参照実装が無かったからである。

形は消費者ごとに組み立てられていた。koyu の `src/draw/plan.ts` が `segmentsFor` と `placeOpening` を呼び、ugatsu の `PlanView.tsx` と `three/buildScene.ts` も**同じ部品を別々に呼んで、自分で組み立てていた**。部品は共有されていても組み立ての規則は共有されていない。**同じ部品から違う形が出る余地が構造的に残っており、実際に違う形が出ていた。**

| 割れていたもの | 実測 |
|---|---|
| **上部吹抜けの投影** — 平面が `wall` と `open` 以外の境界を捨てていた。koyu の `svgPlan` は描く | 同梱例に **11 件** (complex 4・twin 4・tower 1・house 1・office 1)。ugatsu の平面には**一つも出ていなかった** |
| **斜め線分の上の開口** — 平面の帯と扉の軌跡に `seg.diagonal` の枝が無く、3D の壁割りは斜めでは開口を抜かなかった | 斜めの線分は complex 10・twin 39。そこに書かれた開口は 0 件なので、**まだ観測されていない事故**だった |
| **階高** — koyu は「天井高 + 屋根版」、ugatsu は「天井高 + slab」で近似 | 最上階の壁の上端が 150mm 割れる |
| **壁厚の既定 100mm** | `PlanView.tsx:40` と `buildScene.ts:328` と koyu の `plan.ts` と `axo.ts` の**四箇所に別々のリテラル**として在った |
| **開口の z** — 扉 2000 / 窓 1200 / 窓台 800 は ugatsu の発明で、`sill` は台帳の自由語である | koyu は開口の z をそもそも持っていなかった |
| **天井高が決まらないとき** — koyu は `SUF01` (error) で形を作らない。ugatsu は `DEFAULT_H = 2400` で描いていた | **check が赤いのに立体は完成して見える** ([docs/scope.md](../scope.md) §5.2 が「最も危険な行」と書いた箇所) |

koyu 側に `derive(model): Form` が立った (ADR-0040)。`Form` は座標・厚み・z 範囲・向き・対象の同一性だけを持ち、**見た目を一つも持たない**。平面は「分類つきの2Dエンティティ集合」として渡り、切断高さは入力である。これで ugatsu の側の判断が残らなくなった。

## 決定

**1. 形の入口を `formOf(model)` 一つにする。**

`src/lib/form.ts` が `derive` を呼ぶ唯一の頁である。同じモデルには同じ `Form` を返す (WeakMap)。**平面ビューと立体ビューが同じ実体を見ることが、型ではなく同一性で保証される。**

呼び出しが一つであることそのものが、割れる余地を閉じる。11 件の欠落も、150mm の割れも、四重定義の 100mm も、直したのではなく**消えた**。

**2. `PlanView` は「印」を描くだけにする。純関数を一枚挟む。**

`src/lib/planFigure.ts` が `planFigure(form, level): Mark[]` を返し、`PlanView` はそれを SVG へ写す。印は役 (`wall` `rail` `door-arc` `void-above` …) と対象の同一性を持ち、幾何はすべて `Form` から来る。線幅も色も破線のパターンも `PlanView` が役から決める。

**純関数を挟んだのは、検査できるようにするためである。**React の木を DOM 無しで描いても、ストアの初期値しか見えない (zustand の SSR は `getInitialState` を返す)。「描いたものが `Form` と一致する」を機械に言わせるには、描く前に素のデータへ落ちている必要があった。

**3. `buildScene(form, opts)` はモデルを受け取らない。**

立体の側は `Form` だけで立つ。モデルが要るのは二箇所しか無く、どちらも形ではない。

- **色** — `ModelColors` に `byPath(path)` を足した。`Form` は空間のパスしか持たない
- **`spec` の解釈** — 「ガラス / カーテンウォール / サッシ / glass」を透過に写すのは **ugatsu が語の意味を決めている**箇所であり ([docs/scope.md](../scope.md) §5.2)、`glassSpec(model)` という述語として外から渡す。形の中に紛れ込ませない

**4. 埋めていた既定値を捨てる。**

`DEFAULT_H = 2400` も、階高の近似も、扉 2000 / 窓 1200 / 窓台 800 も、壁厚 100 も、ugatsu には無い。**天井高が決まらない空間には立体を作らない** — koyu が形を作らないと決めた場面で、ugatsu も作らない。

残した既定は三つだけで、どれも**原本に対応物を持たない見た目**である — 2.5D の床プレート厚 (120mm)、半屋外を地面として描く板厚 (150mm)、建具の見付け厚の増し (60mm)。

**5. `showOpenings` は建具の表示であって、壁が割れることではない。**

`Form` の壁は最初から開口で割られた区間の列である。割れないようにはできない。トグルが消せるのは扉とガラスの立体だけなので、ラベルを「開口」から「建具」へ改めた。

**6. ゴールデン一致テストを、凍結面「導出の一致」の実体として立てる。**

`test/form.test.ts` が五つを縛る。

1. **形の出所が一つ** — 描画の三頁 (`PlanView.tsx` / `buildScene.ts` / `planFigure.ts`) が koyu の形の部品 (`segmentsFor` `placeOpening` `placeBand` `slabs` `columnsFor` `runSolids` `runDrawsForLevel` `verticalRuns` `heff` `rectToPoly` `isSemiOutdoor` `isCoveredAbove` …) を**取り込まない**。`derive` を取り込むのは `src/lib/form.ts` だけ
2. **立体が `Form` と一致する** — 同梱例 8 本で、シーンに立った箱の集合が `Form` から組み直した期待値と**座標まで一致する**。壁の区間・建具・柱・段板のすべて
3. **平面が `Form` を取りこぼさない** — 全レベルで印の数が役ごとに一致する。省くのは垂れ壁 (切断面より上の壁) と腰壁 (開口の下の壁) の二つだけで、それも数として現れる
4. **上部吹抜けの投影が出る** — 11 件
5. **決まらなければ作らない** — 階高が決まらないモデルで、箱もピック対象も 0 になる

**7. 診断を `checkDiagnostics` へ移す。**

ストアは `check(model)` が返した**文字列**を受け、`/^(?:([^\s:]+):)?(\d+)行目/` で出所を復元していた。koyu が機械向け出力を英語へ揃えた時点で、この正規表現は**黙って壊れた** — エラー一覧のクリックが全部死んでも、画面は何も言わない。構造化診断 `Diagnostic { code, severity, message, line, file, related }` が一次形式である (koyu ADR-0016)。移して、診断コードが画面に出るようになった。

## 棄却した案

**`buildScene(model, form)` — モデルも一緒に渡す。**`spec` の解釈のためだけにモデルが要る。棄却したのは、**形の出所が二つに見える**からである。渡してあるものは、いつか使われる。述語一つを外から渡せば足りる。

**純関数を挟まず、`PlanView` に直接 `Form` を読ませる。**頁数は減る。棄却したのは、**「描いたものが `Form` と一致する」を機械が言えなくなる**からである。凍結面は文で書いても着地しない。

**SVG の文字列でゴールデンを取る。**koyu の `derive.test.ts` は `Form` の sha256 でゴールデンを取っている。ugatsu で同じ手を SVG に対して使うと、**見た目を凍らせてしまう。**凍るのは形であって、線の太さでも色でもない ([docs/scope.md](../scope.md) §1 — 図面の精度は凍結の対象ではない)。だから突き合わせるのは幾何の集合にした。

**ストアで `Form` を先に計算する。**再合成のたびに一度で済み、素直である。棄却したのは**払う必要のない場面があるから**で、twin (延床 141,449㎡) の `derive` は 1,453ms、`check` は 932ms である。面積表とエディタだけを見ているあいだ、この 1.5 秒はどこにも要らない。遅延させ、WeakMap で二度払わないようにした。

**上部吹抜けを ugatsu の側で `boundary type:void` から落とす。**平面のエンティティを待たずに済む。棄却したのは、**割付で落とすと切られた吹抜けが切られる前の姿で出る**からである (koyu spec/derivation.md §8)。落とすのは導出された形でなければならない。

## 帰結と代償

- **上部吹抜けの投影が 11 件すべて出る** (complex 4・twin 4・tower 1・house 1・office 1)。数えたのは「階をまたぐ `boundary type:void` の宣言」で、テストが件数を固定している
- **斜め線分の上の開口が形になる。**壁は芯線に沿って三区間へ割れ、軌跡は法線から決まる。同梱例には一件も無いので、テストが最小の例を立てて縛る
- **`DEFAULT_H = 2400` が消えた。**check が赤いとき、3D は完成して見えるのではなく**空く**
- **代償1 — `koyu 1.0.0-rc.1` はまだレジストリに無い** (公開されているのは 0.15.0 まで)。`package.json` の範囲は `^0.15.0` のままで、開発は `npm run koyu:local` (ADR-0005) がローカルのツリーを見る。**この範囲はいま嘘である** — 0.15.0 に `derive` は無い。公開されたら `package.json` と lockfile を同じ変更で上げる。実際に解決された版は配布HTMLの `<meta name="koyu:version">` に焼き込まれ、テストが実体との一致を縛っている ([docs/scope.md](../scope.md) §6)
- **代償2 — twin で `derive` に 1,453ms かかる。**部品を個別に呼んでいた頃の合計 (約 1,000ms) より重い。ただし平面と立体が二度払っていたのをやめたので、両方を開いている限りでは軽い
- **代償3 — `showOpenings` の意味が変わった。**壁が開口で割れることは形であり、消せない
- **代償4 — 天井高が決まらない空間は 3D から消える。**「描かれない」ことが `SUF01` の可視化であって、欠陥ではない
