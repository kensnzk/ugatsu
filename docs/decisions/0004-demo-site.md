# ADR-0004 (ugatsu): 配布物をそのままデモサイトにする

日付: 2026-07-26 / 状態: 採用 (v0.3) / 前提: ADR-0001 (成果物は単一HTML)

## 文脈

OSSとして読まれるには「インストールせずに触れる一枚」が要る。READMEのスクリーンショットは、テキストが打った端から平面になるという主題 — このビューワーの唯一の主張 — を伝えない。触ってもらうしかない。

## 決定

**デモサイトは配布物そのもの。** `npm run build` が出す `dist/index.html` (単一HTML) を Vercel が静的配信する。デモ専用のビルドも、デモ専用のコードも持たない。公開先は https://ugatsu.dev、GitHub連携で main への push がそのまま本番、PRにはプレビューURLが付く。ホスティングの設定は `vercel.json` の数行 (vite / npm ci / dist と最小のヘッダ) に閉じ、アプリ側にホスティングの痕跡は無い。

例外は `public/og.png` — リンクプレビュー用に実画面を撮ったものだけがweb専用の副産物になる。絶対URLでしか参照しないので、配布HTMLの自己完結性は壊れない (手渡された一枚は og.png を読まない)。

## 代替案

GitHub Pages は静的配信としては同じだが、PRごとのプレビューが無く、koyucore.dev と運用が二箇所に割れる。デモ用に通常のViteビルド (JS/CSS分割) へ切り替えればキャッシュは細かく効くが、brotli 316KB の一枚に対してビルド経路を二本持つ代償のほうが大きい — 単一HTMLであること自体がこのプロジェクトの主張でもあり、デモがその主張から外れるのは本末転倒。

## 帰結と代償

触れる場所ができ、READMEの冒頭がリンクになる。デモとリリース物が同一なので「デモでは動くのに配ったHTMLでは動かない」が構造的に起きない。

代償: 初回ロードは単一HTMLの一括 (brotli 316KB)、二度目以降はETagの再検証で304 — 分割キャッシュより素朴だが、この規模では体感差は出ない。デモに保存は無く (ブラウザの中だけ)、書き換えた結果を残すには「書き出し」で自分のファイルにする。まだない: 埋め込み用の軽量モード、og.png の自動更新 (画面が変わったら撮り直す)。
