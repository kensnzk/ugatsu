# ADR-0003 (ugatsu): 原本は一枚のテキストからレイヤー群へ

日付: 2026-07-23 / 状態: 採用 (v0.2) / 前提: koyu ADR-0010 (import合成・建具アセット・明示位置)

## 文脈

koyu v0.6 で一棟が `import` によるファイル群 (base層+分担レイヤー) になった。ビューワーの原本は「一枚のソーステキスト」だったが、これでは合成の例が開けず、分担という主題 — 各フロアを各自が書き、一棟へのマージでコンフリクトが検査される — が見えない。

## 決定

**原本は `files + entry` (レイヤー群と合成の入口)。** 単一ファイルは1枚のレイヤー群として同じ経路を通る。合成は koyu の `parseFiles` (仮想ファイル群 — ブラウザにfsは無い) の一本呼びで、ビューワーは合成の意味論を一切持たない。エディタはタブでレイヤーを行き来し (◈ = base層)、編集は activeFile への操作 → 全体を再合成。コンフリクトもcheckのエラーも出所レイヤー:行つきで届き、クリックでそのタブの行へ飛ぶ。複数 `.muro` の同時ドロップはレイヤー群として開く (entryは `import` を持つファイルと推定)。配布用HTMLはレイヤー群をJSONのまま埋め込み、開いた側でも分担が見える。

## 代替案

タブではなく「合成済みの一枚に展開して編集」は、原本 (レイヤーの境界 = 分担の境界) を壊す — 展開はビューであって原本ではない。ビューワー側でのimport解決の再実装は、koyuとの意味論の二重管理になる (parseFilesの追加をkoyu側に求めたのはこのため)。

## 帰結と代償

分担の単位がそのままレビューの単位として画面に出る。単一ファイルの体験は不変。まだない: レイヤーの追加・削除・改名のUI (原本の編集はテキストで足りるが、ファイル構成の編集はまだファイルシステムの仕事)、タブ間の同時表示 (二枚並べての比較)。
